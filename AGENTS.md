# AGENTS.md

Two toolchains in one repo: a TypeScript VS Code extension (`src/`) that ships, and a Python toolchain (`build-data.py`, `tests/`) used only to generate the offline HTMX catalog the extension consumes. Keep both in mind — most edits touch one side, but the catalog ties them together.

## Commands

Run from repo root. `just` recipes wrap the same commands.

- Install: `npm install` then `uv sync --all-groups` (Python) — also `just init` to add prek hooks.
- Lint TS: `npm run lint` (eslint) · `npm run check-types` (tsc --noEmit)
- Lint Python: `uv run ruff check .` · `uv run ruff format --check .` (or `just lint` to autofix)
- Full test: `npm test` (runs `npm run test:unit` AND `uv run pytest -q`)
- TS unit only: `npm run test:unit` (compiles first, then `node --test out/test/*.test.js`)
- Python only: `uv run pytest -q`
- Single Python test: `uv run pytest tests/test_build_data.py::test_name -q`
- Extension-host tests: `npm run test:extension` — downloads VS Code 1.90.2, installs `batisteo.vscode-django`, runs `src/test/suite/index.ts`. On Linux CI uses `xvfb-run -a`; locally on macOS no wrapper needed.
- Compile (no test): `npm run compile`
- Package VSIX: `npm run package`

## Catalog regeneration (the non-obvious trap)

`htmx.catalog.json` is committed and is the extension's offline data source — it is NOT generated at runtime. Pinned upstream HTMX versions: `2.0.10` and `4.0.0-beta6` (constants in `build-data.py`).

Regenerate with `npm run build-data` (= `uv --cache-dir .cache/uv run python build-data.py`). CI fails if `git diff --exit-code -- htmx.catalog.json` shows drift, so after changing `build-data.py` or its inputs, regenerate AND commit the catalog together.

CI also runs `uv run python scripts/check-htmx-pins.py` (or `just check-pins`) to fail when the pinned tags drift from the latest `bigskysoftware/htmx` git tags. Fix a pin-staleness failure by bumping `DEFAULT_HTMX_V*_VERSION` in `build-data.py`, regenerating the catalog, and committing both together — the script queries the public GitHub `/tags` endpoint, so unauthenticated rate limits apply.

## CI order (match this locally before pushing)

`npm run lint` → `npm run check-types` → `uv run ruff check .` + `uv run ruff format --check .` → `uv run pytest -q` → `npm run test:unit` → `npm run build-data` (then verify catalog diff is clean) → `npm run test:extension` → `npm run package`. `just check` runs lint + test + `prek run --all-files` — close enough for local pre-push.

## Layout & boundaries

- `src/` — TypeScript extension source; wired entry is `src/extension.ts` (`package.json` `main` -> `out/extension.js` after compile). Do not edit `out/` — it's compiled.
- `src/test/*.test.ts` are unit tests run by `node --test`; `src/test/suite/index.ts` is the extension-host suite; `src/test/runTest.ts` bootstraps VS Code + a throwaway workspace.
- `build-data.py`, `tests/` — Python dev tooling only. Python is excluded from the VSIX via `.vscodeignore`; never add runtime Python deps to the extension.
- `snippets/django-htmx.json` — packaged snippets, contributed via `package.json` `contributes.snippets`.
- `docs/` → built to `site/` via `zensical` (`just docs`, `just docs-build`, `just docs-strict`). Docs deploy on push to `main` via `.github/workflows/docs.yml`.
- `images/`, `demo-*.png` — Marketplace/demo assets, regenerated by `just demo-assets`.

## Python env notes

- Python 3.12 (`.python-version`), managed by `uv` with cache pinned to `.cache/uv` (see `package.json` `build-data` script and `justfile`). The `.cache/` dir is gitignored.
- `ty.toml` configures the `ty` type checker (dev dep); `ruff.toml` extends-excludes build dirs.
- `build-data.py` is exempt from E501 in ruff (`per-file-ignores`).
